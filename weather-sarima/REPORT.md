# SARIMA Forecasting Report

## Overview

SARIMA extends ARIMA with seasonal autoregressive and moving-average terms,
making it suitable for hourly weather series with repeated daily patterns. In
this project, the 24-hour-ahead multivariate forecast is produced by **seven
independent univariate SARIMA models**, one per target variable:

```text
temp, rh, dew, pressure, cloud, wx, wy
```

Each SARIMA model forecasts its own variable for the next 24 hours. The seven
outputs are then stacked into the required 24 x 7 forecast block. This design is
simple, deterministic, and interpretable, but it does not directly model
cross-variable dependencies such as the relationship between temperature, dew
point, humidity, and pressure.

## Mathematical Formulation

A seasonal ARIMA model is written as:

$$
\text{SARIMA}(p,d,q)(P,D,Q)_s
$$

where $(p,d,q)$ are the non-seasonal orders, $(P,D,Q)$ are the seasonal orders,
and $s$ is the seasonal period. For hourly data, this project uses $s=24$ to
represent daily seasonality.

The model can be expressed as:

$$
\Phi_P(B^s)\,\phi_p(B)\,(1-B)^d(1-B^s)^D y_t
= \Theta_Q(B^s)\,\theta_q(B)\,\varepsilon_t
$$

where:

- $B$ is the backshift operator.
- $\phi_p(B)$ is the non-seasonal autoregressive polynomial.
- $\theta_q(B)$ is the non-seasonal moving-average polynomial.
- $\Phi_P(B^s)$ is the seasonal autoregressive polynomial.
- $\Theta_Q(B^s)$ is the seasonal moving-average polynomial.
- $\varepsilon_t$ is the residual error term.

The default model used by the implementation is:

```text
SARIMA(order=(1, 0, 1), seasonal_order=(1, 0, 1, 24), trend="c")
```

This includes one non-seasonal AR term, one non-seasonal MA term, one seasonal
AR term, one seasonal MA term, and a constant trend.

## Model Selection

The implementation supports a candidate grid for both `order` and
`seasonal_order`. Candidate strings are passed from the command line and can
contain one or more configurations, for example:

```powershell
python weather-sarima/train.py --order "1,0,1;2,0,1" --seasonal-order "1,0,1,24;0,0,1,24"
```

For each target variable, the pipeline:

1. Fits each candidate SARIMA model on the 2021-2023 training split.
2. Evaluates the candidate on the 2024 validation split.
3. Uses rolling-origin validation with horizon `H = 24` and step `24`.
4. Selects the model with the lowest validation MAE.
5. Uses training AIC as a tie-breaker when validation MAE is equal.

The validation origins are generated by:

```python
range(0, len(validation_series) - horizon + 1, step)
```

With `len(validation_series) = 8784`, `horizon = 24`, and `step = 24`, the
starts are:

```text
0, 24, 48, ..., 8760
```

The term `- horizon` ensures that each origin still has a full 24-hour
validation window. The `+ 1` is required because Python `range()` excludes the
stop value.

## Pipeline Overview

The SARIMA pipeline is split into a training stage and a prediction stage.
Training selects and saves one fitted model per target variable; prediction
reloads those models and evaluates the 2025 rolling-origin forecasts without
fitting again.

```text
Hourly data
    |
    |-- preprocess + wind decomposition
    |
    |-- chronological split: train 2021-2023, val 2024, test 2025
    |
    |-- for each target variable:
    |      fit candidate SARIMA models on train
    |      score candidates on validation rolling forecasts
    |      select lowest validation MAE
    |      save fitted result
    |
    |-- load saved models
    |
    |-- append validation history with refit=False when needed
    |
    |-- rolling 24h forecasts over 2025
    |
    |-- aggregate MAE/RMSE overall, per horizon, and per variable
```

Because SARIMA is univariate, the pipeline repeats the same modelling process
seven times and then stacks the forecasts into one multivariate output block.

## Training Procedure

### One Model Per Target

Seven independent SARIMA models are trained, one for each target variable. Each
model uses only the past values of its own target series. This makes SARIMA a
univariate statistical baseline rather than a multivariate learner.

### Data Usage

By default, model parameters are fitted on the 2021-2023 training period. The
2024 validation period is used for model selection. During test forecasting,
the validation observations can be appended with `refit=False`, so the model
conditions on true pre-test history without changing its fitted parameters.

### Optional Final Refit

If `--fit-through-val` is used, the selected model is refitted on 2021-2024
before forecasting the 2025 test set. This uses all pre-test data for the final
statistical baseline.

### Determinism

SARIMA fitting is deterministic for a fixed dataset and model configuration.
The random seed in the pipeline only affects bootstrap confidence intervals for
the reported metrics, not the SARIMA model itself.

### SARIMA Training and Evaluation Hyperparameters

| Parameter | Value |
|---|---|

## Prediction Pipeline

1. **Preprocessing:** parse time, enforce hourly frequency, clean wind values,
   interpolate incidental gaps, and convert wind direction into `wx` and `wy`.
2. **Model loading:** load the saved SARIMA model for each target variable from
   `weather-sarima/results/models/`.
3. **Pre-test update:** if the model was fitted only on 2021-2023, append the
   2024 validation observations with `refit=False` before the first 2025
   forecast.
4. **Rolling-origin prediction:** at each origin $t$, forecast
   $t+1,\dots,t+24$ for each target variable.
5. **Stacking:** combine the seven univariate forecasts into one 24 x 7
   forecast block.
6. **Evaluation:** compare predictions with actual 2025 observations and
   compute MAE/RMSE overall, per horizon, and per variable.

## Algorithm

```text
Input:
  Hourly target series
  V = 7 targets
  H = 24 forecast horizon
  S = 24 rolling-origin step

Training:
  Preprocess data and split chronologically into train, validation, and test

  For each target variable v:
    Fit each candidate SARIMA model on the training series
    Forecast the validation series with rolling origins
    Compute validation MAE and RMSE
    Select the candidate with the lowest validation MAE
    Refit on the final fit scope if required
    Save the selected fitted model

Prediction:
  Load saved models

  For each 2025 test origin t with step S:
    Forecast t+1, ..., t+H for all seven targets
    Stack forecasts into a matrix with shape H x V
    Compare with actuals and aggregate MAE/RMSE
```

## Experimental Results

Evaluated by rolling-origin over the 2025 test year (`N = 365` origins, real
scale), the current SARIMA run obtains an **overall MAE of 6.41** with 95%
bootstrap CI `[6.23, 6.60]` and an **overall RMSE of 13.02** with CI
`[12.55, 13.49]` (see the overall metrics table). The per-variable breakdown
shows that temperature, dew point, and pressure are forecast relatively
accurately, while `cloud` is the hardest target with MAE `26.93` and RMSE
`32.41`. This matches the EDA observation that cloud cover is noisy, bounded,
and weakly linearly correlated with the other variables.

Forecast error increases with lead time: MAE is `2.26` at horizon `h = 1` and
rises to `7.75` at horizon `h = 24`. This is expected because uncertainty
accumulates as the forecast moves further away from the origin.

## Diagnostic Summary

The statistical diagnostics show that the target series are stationary on the
training split, but the fitted residuals still contain structure. This is
expected for a compact univariate SARIMA baseline on complex weather data.

| Diagnostic | Result | Interpretation |
|---|---|---|
| ADF stationarity | PASS, all 7 targets | Train series reject the unit-root null; `d = 0` is acceptable. |
| Convergence | 6/7 converged | `pressure` did not report convergence in the current run. |
| Ljung-Box, lag 24 | FAIL, all 7 targets | Residual autocorrelation remains after fitting. |
| Jarque-Bera normality | FAIL, all 7 targets | Residuals are non-normal, especially for bounded/noisy variables. |
| Bootstrap CI, overall MAE | `[6.2320, 6.5963]` | Confidence interval is narrow relative to the MAE. |
| Bootstrap CI, overall RMSE | `[12.5457, 13.4889]` | Metric estimate is stable across resampled origins. |

**ADF.** All seven training series are stationary at the 5% level, so the
default non-seasonal and seasonal differencing orders remain zero in the current
configuration.

**Residual autocorrelation.** Ljung-Box rejects the white-noise null for every
target at lag 24. This means the univariate SARIMA models leave some temporal
structure in the residuals, especially around daily patterns and longer-memory
weather regimes.

**Residual normality.** Jarque-Bera rejects normality for every target. This is
unsurprising because cloud cover is bounded and bimodal, and wind components can
be heavy-tailed during gust events. Analytical Gaussian intervals should
therefore be interpreted cautiously.

## Analysis

### What SARIMA Does Well

SARIMA performs best on smoother variables with strong temporal persistence.
Temperature, dew point, and pressure have MAE values close to 1-1.4 in native
units, showing that the model captures much of their daily and short-term
autocorrelation. The seasonal period of 24 hours is well aligned with the
diurnal cycle visible in the dataset.

The model is also lightweight and deterministic. Once the order and seasonal
order are fixed, repeated runs on the same data produce the same fitted model,
making SARIMA useful as a reproducible statistical baseline.

### What SARIMA Struggles With

Cloud cover is the hardest target, with MAE `26.93` and RMSE `32.41`. This is
consistent with its bounded, often bimodal behaviour: cloud cover can jump
sharply between clear and overcast states, and those transitions are difficult
to infer from a single univariate history.

Wind components also have higher error than temperature, dew point, and
pressure. Gusts and direction changes can be abrupt at hourly resolution, so a
linear univariate model has limited information for predicting them 24 hours
ahead.

The main structural limitation is that each SARIMA model sees only one target
variable. It cannot directly use cross-variable information such as
temperature-dew point coupling, humidity-cloud relationships, or pressure
changes that may precede wind shifts.

### Practical Trade-Off

SARIMA is valuable as an interpretable baseline: it is simple, fast relative to
deep learning, and its assumptions are transparent. However, the diagnostics
show residual autocorrelation and non-normality, so it does not fully explain
the data-generating process. For final model comparison, SARIMA should be
interpreted as a deterministic statistical reference point rather than the
expected best-performing model.

## Implementation Notes

Training and prediction are separated into two scripts:

```powershell
python weather-sarima/train.py
python weather-sarima/predict.py
```

`train.py` selects and saves the fitted SARIMA models. `predict.py` loads the
saved models and evaluates the 2025 rolling-origin forecasts without
retraining. The previous end-to-end command is still available:

```powershell
python weather-sarima/run.py
```

The main output files are:

```text
results/forecasts.csv
results/metrics.csv
results/overall_metrics.csv
results/per_horizon_metrics.csv
results/per_variable_metrics.csv
results/diagnostics.txt
results/plots/
results/models/
```
